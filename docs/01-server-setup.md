# Server setup

Everything runs on one cloud VM: the Wazuh indexer, manager, Filebeat and dashboard (the "all-in-one" install).
I only reach it over WireGuard. The two agent ports are the only thing open to the internet.

## What you need

| Item | Notes |
|---|---|
| VM | Ubuntu 24.04, 4 GB RAM minimum (tight, but it works once old alerts are cleaned up, see the retention part coming later), 2 vCPU, 40+ GB disk. Any provider; a small cloud VM costs a few euros a month. Turn on the provider's backups. |
| Your PC | Windows with the [WireGuard app](https://www.wireguard.com/install/) and OpenSSH (built in) |
| Password manager | Every password in this guide goes there first |

Placeholders: server VPN address `10.10.0.1`, your PC `10.10.0.2`, VPN subnet `10.10.0.0/24`,
public IP `<SERVER_PUBLIC_IP>`, Linux user `admin`. Pick your own private range if you like.

## 1. Base system (as root on the VM, provider's web console or first SSH login)

Create your user with an SSH key, then lock SSH down to keys only:

```bash
adduser admin && usermod -aG sudo admin
mkdir -p /home/admin/.ssh && nano /home/admin/.ssh/authorized_keys     # paste your PUBLIC key
chown -R admin:admin /home/admin/.ssh && chmod 700 /home/admin/.ssh && chmod 600 /home/admin/.ssh/authorized_keys
printf 'PasswordAuthentication no\nPermitRootLogin no\n' > /etc/ssh/sshd_config.d/10-hardening.conf
systemctl restart ssh
apt update && apt upgrade -y
```

Make the key on the PC first (PowerShell): `ssh-keygen -t ed25519 -f $HOME\.ssh\wazuh` (use a passphrase).

## 2. WireGuard (server)

```bash
apt install -y wireguard
cd /etc/wireguard && umask 077
wg genkey | tee server.key | wg pubkey > server.pub
cat > wg0.conf <<EOF
[Interface]
Address = 10.10.0.1/24
ListenPort = 51820
PrivateKey = $(cat server.key)

[Peer]
# your PC
PublicKey = <PC_PUBLIC_KEY>
AllowedIPs = 10.10.0.2/32
EOF
```

On the PC: WireGuard app > Add Tunnel > Add empty tunnel. It shows the PC's public key; put it in
`<PC_PUBLIC_KEY>` above. Tunnel config on the PC:

```ini
[Interface]
PrivateKey = (generated by the app)
Address = 10.10.0.2/32

[Peer]
PublicKey = <contents of /etc/wireguard/server.pub>
AllowedIPs = 10.10.0.0/24
Endpoint = <SERVER_PUBLIC_IP>:51820
PersistentKeepalive = 25
```

Start it on the server and enable it at boot (otherwise a reboot locks you out):

```bash
systemctl enable --now wg-quick@wg0
systemctl is-enabled wg-quick@wg0     # enabled
```

Activate the tunnel in the app, then from the PC: `ping 10.10.0.1`.

## 3. Firewall (UFW + the provider's firewall)

```bash
ufw default deny incoming && ufw default allow outgoing
ufw allow 51820/udp
ufw allow from 10.10.0.0/24 to any port 22 proto tcp
ufw allow from 10.10.0.0/24 to any port 443 proto tcp
ufw allow from 10.10.0.0/24 to any port 55000 proto tcp
ufw allow 1514/tcp
ufw allow 1515/tcp
ufw enable && ufw status verbose
```

Mirror the same rules in your cloud provider's firewall. Test SSH over the VPN before closing the
public SSH port:

```powershell
ssh -i $HOME\.ssh\wazuh admin@10.10.0.1
```

1514 and 1515 stay open to the internet on purpose, so laptops report from anywhere without WireGuard.
1514 only accepts registered agents (per-agent key, encrypted); 1515 needs the enrollment password (step 5).

## 4. Install Wazuh all-in-one

Follow the [Wazuh quickstart](https://documentation.wazuh.com/current/quickstart.html); at the time of
writing it is:

```bash
curl -sO https://packages.wazuh.com/4.14/wazuh-install.sh && sudo bash ./wazuh-install.sh -a
```

It prints the dashboard `admin` password at the end. Save it in the password manager. All generated
passwords are also in `/root/wazuh-install-files.tar`:

```bash
tar -O -xf /root/wazuh-install-files.tar wazuh-install-files/wazuh-passwords.txt
```

Open `https://10.10.0.1` (VPN on), accept the self-signed certificate, log in as `admin`.

Lock the Wazuh package repo between upgrades so `apt upgrade` never upgrades Wazuh by surprise:

```bash
sed -i 's/^deb /#deb /' /etc/apt/sources.list.d/wazuh.list && apt update
```

## 5. Enrollment password (port 1515)

Without it, anyone who finds port 1515 can register an agent. Generate the password in the password
manager, then on the server:

```bash
sudo -i
read -rs P; echo ${#P}        # paste ONCE, Enter; the number must equal the password length
printf '%s\n' "$P" > /var/ossec/etc/authd.pass; unset P
chown root:wazuh /var/ossec/etc/authd.pass && chmod 640 /var/ossec/etc/authd.pass
```

In `/var/ossec/etc/ossec.conf`, inside `<auth>`, set `<use_password>yes</use_password>`, then
`systemctl restart wazuh-manager`.

## 6. Add a Windows agent

Download the agent MSI of the same version as the manager from the Wazuh docs, then in an
Administrator PowerShell in the download folder:

```powershell
$p = Read-Host "Enrollment password" -AsSecureString
$plain = [Runtime.InteropServices.Marshal]::PtrToStringAuto([Runtime.InteropServices.Marshal]::SecureStringToBSTR($p))
msiexec /i wazuh-agent-4.14.8-1.msi /q WAZUH_MANAGER="<SERVER_PUBLIC_IP>" WAZUH_REGISTRATION_PASSWORD="$plain" WAZUH_AGENT_NAME="LAPTOP-1" WAZUH_AGENT_GROUP="default"
Remove-Variable plain, p
NET START WazuhSvc
```

On the server, `/var/ossec/bin/agent_control -l` lists it as Active within a minute.
Without the password, authd answers `ERROR: Invalid password`. Next: [Windows logging](04-windows-logging.md).

## 7. Memory: add a swap file

A 4 GB node is tight. A small swap file makes a spike slow the box down instead of the kernel's OOM killer
stopping the indexer:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
echo 'vm.swappiness=10' > /etc/sysctl.d/99-swap.conf && sysctl --system
free -h
```

Check memory now and then with `free -h`. The indexer heap is 1 GB by default (`-Xms1g/-Xmx1g` in
`/etc/wazuh-indexer/jvm.options`), about 75 % used is normal. The real fix for memory pressure on a small
node is fewer shards (the retention part, coming later).

## Daily use

1. WireGuard app: activate the tunnel.
2. Dashboard: `https://10.10.0.1`.
3. SSH: `ssh -i $HOME\.ssh\wazuh admin@10.10.0.1`, then `sudo -i`.
4. VPN broken? Use the provider's web console (no VPN needed), log in, `systemctl enable --now wg-quick@wg0`.
